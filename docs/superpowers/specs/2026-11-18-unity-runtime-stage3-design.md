# KGBone 유니티 런타임 3단계 설계: 그리기 마무리와 게임용 재생 조작

작성: 2026-11-18. 상태: 승인 대기. 앞 단계: `2026-11-16-unity-runtime-stage1-design.md`, `2026-11-17-unity-runtime-stage2-design.md`.

## 1. 목적과 이유

2단계까지 유니티 런타임은 에디터에서 만든 애니메이션 **하나를 그대로 재생**한다. 게임에서 실제로 캐릭터를 쓰려면 두 가지가 모자란다.

1. **에디터와 다르게 그려지는 것**: 클리핑은 자르지 않고 그리며, 시퀀스는 셋업 프레임만 보인다(가져올 때 경고).
2. **게임 코드가 재생을 조작하는 것**: 사용자가 쓰려는 장면(사용자 답):
   - 걸으면서·달리면서 공격한다 → 걷기↔달리기는 부드럽게 넘어가고, 공격은 그 위에 겹쳐 키가 있는 본만 덮는다(다리는 계속 걷는다). 공격이 끝나면 겹친 것이 서서히 빠진다.
   - 무기를 갈아 끼운다 → 슬롯 첨부물 바꾸기, 몸 스킨 + 무기 스킨 합치기.
   - 마우스를 따라 고개를 돌린다 → 게임 코드가 매 프레임 본 값을 정한다.

API 모양은 **번호 트랙**(방법 A, 사용자 선택)으로 한다. 걷기 + 공격 + 나중에 표정·피격 같은 겹침을 더해도 API를 다시 깨지 않기 위해서다.

## 2. 목표 · 비목표 · 반목표

### 목표 (3단계 완료 조건)
1. **시퀀스**: 시퀀스 키(모드 7종: hold, once, loop, pingpong, onceReverse, loopReverse, pingpongReverse, 그리고 프레임 간격)에 따라 프레임 이미지가 바뀐다. 가져오기는 모든 프레임 이미지를 텍스처에 묶는다. 핵심(`anim/attachment_keys.rs`의 `sequence_frame`, `pose/draw.rs`의 `sequence_path`)과 그리기 목록 정답 비교로 같다.
2. **클리핑**: 클리핑 슬롯부터 end 슬롯까지 그려지는 삼각형을 클립 다각형으로 자른다(반전·볼록 옵션 포함). 핵심(`pose/clipping.rs`, `pose/draw.rs`)과 그리기 목록(정점·uv·인덱스) 정답 비교로 같다(오차 1e-3).
3. **트랙**: 번호 트랙에 애니메이션을 놓고, 같은 트랙에서 바꿀 때 지정한 시간 동안 섞어 넘어가며, 윗 트랙은 아랫 트랙 결과 위에 자기 키가 있는 값만 덮는다. 예약(끝나면 다음 것), 트랙 비우기(서서히 빠짐), 트랙별 끝남 이벤트가 있다.
4. **첨부물·스킨**: 코드로 슬롯 첨부물을 바꾸고, 스킨 여러 개를 합쳐 켠다.
5. **본 덮어쓰기**: 코드로 본의 로컬 값(회전·위치·크기)이나 월드 위치·월드 회전을 정한다. 덮어쓰기는 애니메이션 뒤·제약 앞에 들어가서, IK 대상 본을 옮기면 IK가 따라온다.
6. 아무 새 API도 쓰지 않으면 결과가 2단계와 **완전히 같다**(기존 정답 912개 그대로 통과, 기존 컴포넌트 사용법 그대로).
7. 클리핑·시퀀스 가져오기 경고가 없어진다.

### 비목표
- Animator·Timeline 연동(필요하면 4단계).
- 트랙별 더하기(additive) 섞기, 트랙에 본 마스크 지정(키가 있는 값만 덮는 규칙으로 충분하다고 본다. 필요해지면 추가).
- 루트 모션(애니메이션의 루트 이동을 GameObject 이동으로 바꾸기).
- 에디터 정지 상태에서 물리 미리보기.
- 에디터(웹 앱)에 트랙·섞기 기능을 넣는 것. 이번 단계는 유니티 런타임만 바꾼다. 핵심 계산은 바꾸지 않는다.

### 반목표
- 새 API를 안 쓰는 기존 사용자의 화면·동작이 바뀌는 것(목표 6).
- 섞는 도중 본이 셋업 포즈 쪽으로 꺼졌다 돌아오거나, 섞기가 끝나는 순간 툭 튀는 것.
- 공식 런타임 코드나 그 API 문서를 참고하는 것(클린룸, CLAUDE.md 1장). 트랙 API는 이 문서의 정의만 따른다.

## 3. 제약 조건
- 1·2단계 설계 3장의 제약을 그대로 따른다(클린룸, Unity 6 + URP, 계산부는 순수 C# 9, CI에서는 dotnet만).
- 핵심(Rust) 계산은 바꾸지 않는다. 시퀀스·클리핑에서 핵심 버그로 보이는 것을 찾으면 2단계와 같이 C#은 핵심과 같게 옮기고 GAPS.md에 적어 보고한다.
- 트랙·첨부물·스킨 합치기·본 덮어쓰기는 핵심에 없으므로 정답 비교 대신 계산부 단위 테스트(dotnet)와 EditMode 테스트로 확인한다. 그래서 이 부분의 계산은 되도록 **계산부(`Runtime/Core`)에 두고** 컴포넌트는 얇게 감싼다.
- 매 프레임 메모리 할당을 늘리지 않는다(1단계 원칙: 결과 인스턴스 재사용). 섞기용 포즈 버퍼는 만들어 두고 재사용한다(5.3).

## 4. 방법 (Approaches)

| 방법 | 내용 | 결과 |
|---|---|---|
| **A. 번호 트랙** | `SetAnimation(트랙, 이름, 반복, 섞는 시간)`, `AddAnimation` 예약, `ClearTrack`, 트랙별 끝남 이벤트 | **채택(사용자 선택).** 걷기 + 공격 + 표정처럼 겹침이 늘어도 같은 구조이고, "공격 끝나면 빠지기"를 예약 하나로 해결한다 |
| B. 기본 + 겹침 한 층 | `Play(이름, 반복, 전환 시간)`, `PlayOverlay`/`StopOverlay` | 제외. 겹침이 둘 이상 필요해지면 API를 깨야 한다 |
| C. 매 프레임 콜백만 | 사용자가 섞기를 직접 짠다 | 제외. 쓰는 쪽 부담이 커서 목적(게임에서 바로 쓰기)에 맞지 않는다 |

진행은 2단계와 같이 **세 묶음**, 묶음마다 push하고 CI를 확인한다(설계 판단):
① 시퀀스 + 클리핑(정답 비교 있음) ② 트랙·섞기 ③ 첨부물·스킨 합치기·본 덮어쓰기.

## 5. 설계

### 5.1 계산 순서
핵심 순서(2단계 5.1)에 트랙·덮어쓰기를 끼운다.

셋업 → **트랙 0부터 위로 차례로 적용**(5.3) → **첨부물 덮어쓰기** → **로컬 본 덮어쓰기** → 활성 본 판정(합친 스킨 기준) → 월드 계산 → **월드 덮어쓰기**(해당 본과 자식의 월드를 다시 계산) → 물리 reset 처리 → 활성 제약을 배열 순서대로 → 그리기 목록(**시퀀스 프레임, 클리핑**) → 이벤트.

새 API를 쓰지 않으면 트랙은 0번 하나, 섞기 없음, 덮어쓰기 없음, 스킨 하나라서 2단계와 같은 경로를 탄다.

### 5.2 묶음 ①: 시퀀스와 클리핑 (`Runtime/Core`, 가져오기)
- **시퀀스**
  - 불러오기: 애니메이션의 `sequence` 타임라인(지금은 읽고 버림, `KGBoneLoader.cs`)을 모델에 저장한다. 키 값: `v[0]` 시작 프레임, `v[1]` 프레임 간격(초), `s` 모드.
  - 적용: 포즈 상태에 (슬롯, 첨부물) → 프레임 번호를 두고, 핵심 `sequence_frame`과 같은 규칙으로 정한다(계단 키, 간격 0이면 시작 프레임 고정, 범위 밖은 끝 프레임으로 자름).
  - 그리기: 프레임 번호로 이미지 경로를 만든다(핵심 `sequence_path`: `start + 번호`를 `digits` 자리로 0 채움). 키가 없으면 지금처럼 셋업 프레임.
  - 가져오기: `ImagePaths`가 시퀀스 첨부물의 **모든 프레임**(`start` ~ `start + count − 1`) 경로를 내도록 바꾼다. 없는 프레임 이미지는 지금처럼 "이미지를 찾을 수 없습니다" 경고를 낸다.
- **클리핑**
  - `pose/clipping.rs`를 줄 단위로 옮긴다(`Clipper`: 클립 다각형을 볼록 조각으로 나누기 — convex면 볼록 껍질, 아니면 귀 자르기; 보통은 조각별 반평면 자르기, inverse는 조각을 차례로 빼기; 결과 다각형 부채꼴 삼각형화, uv는 무게중심 좌표로 다시 계산, 넓이 0 버림).
  - 그리기 목록: 핵심 `draw.rs`처럼 clipping 첨부물이 있는 슬롯에서 자르기를 시작하고 end 슬롯(포함)에서 끝낸다. 클리핑 슬롯 자체는 그리지 않는다. 클립 다각형 정점은 가중치·deform까지 반영한 월드 좌표.
  - 자른 결과는 기존 `DrawItem`(위치·uv·인덱스)에 그대로 담으므로 컴포넌트·셰이더는 바꾸지 않는다.
- 가져오기 경고 두 줄(클리핑·시퀀스)을 없앤다.

### 5.3 묶음 ②: 트랙과 섞기
**계산부**: 새 클래스(예: `AnimationTracks`)가 트랙 목록을 들고, 매 프레임 `Update(dt)`로 시간을 진행하고 `Apply(pose)`로 포즈에 적용한다. 컴포넌트는 이것을 감싼다.

**트랙 하나의 상태**: 지금 항목(애니메이션, 반복, 시간, 섞는 시간·지난 섞기 시간, 이전 항목), 예약 목록, 트랙 비율(`Alpha`, 기본 1).

**섞기 규칙**(설계 판단, 반목표 "꺼짐·튐 없음"을 위해 두 포즈를 만들어 섞는다):
- 트랙 n을 적용하기 직전 포즈를 R이라 하자(트랙 0이면 셋업 포즈).
- X = R에 이전 항목을 비율 `Alpha`로 적용한 포즈, Y = R에 지금 항목을 비율 `Alpha`로 적용한 포즈. 이전 항목이 없으면(빈 트랙에서 시작) X = R, 지금 항목이 비어 가는 중이면(트랙 비우기) Y = R.
- 결과 = X와 Y를 `t = 지난 섞기 시간 / 섞는 시간`(0~1)으로 섞은 것. 숫자 값은 선형, 각도는 짧은 쪽, 이산 값(첨부물·그리기 순서·시퀀스 모드 등)은 t ≥ 0.5면 Y. 2단계에서 넣은 `AnimationApplier.Apply(…, alpha)`의 같은 규칙을 쓴다.
- 이렇게 하면 걷기→달리기에서 두 애니메이션 모두 키가 있는 다리 본은 걷기 포즈에서 달리기 포즈로 곧게 넘어가고(셋업 쪽으로 꺼지지 않음), 한쪽에만 키가 있는 본도 끝에서 튀지 않는다.
- 섞지 않는 동안(이전 항목 없음)은 R에 지금 항목을 한 번만 적용한다(포즈 하나, 2단계와 같은 경로).
- 윗 트랙은 "자기 키가 있는 값"만 R에서 바뀐다(키 없는 값은 X·Y·R이 같으므로 섞어도 R 그대로). 그래서 공격 트랙이 팔만 키를 가지면 다리는 아랫 트랙(걷기)을 따른다.
- **섞는 도중에 또 바꾸면**(섞는 중 `SetAnimation`, 빠지는 중 `ClearTrack` 등): 그 순간 그 트랙이 R 위에 바꿔 놓은 결과(트랙 n 적용 뒤 포즈와 R의 차이가 아니라, 트랙 n 적용 뒤 포즈 그 자체)를 **얼려 둔 포즈**로 저장하고, 이후 X 대신 이 얼린 포즈를 쓴다(설계 판단). 이전 항목들을 줄줄이 묶지 않으므로 버퍼 수가 정해진다. 얼린 포즈는 움직이지 않으므로 새 섞기 동안 그 트랙의 옛 움직임은 멈춘 채 빠진다(튀지 않는 것이 우선). 얼린 포즈는 그 트랙의 섞기가 끝나면 버린다. 윗 트랙의 얼린 포즈는 "그 트랙 키가 있던 값"만 담아, 섞는 동안 아랫 트랙이 바뀌어도 키 없는 값은 R을 따르게 한다.
- 포즈 상태 버퍼: X·Y용 공용 둘 + 얼린 포즈가 필요한 트랙마다 하나(처음 필요할 때 만들고 재사용). 매 프레임 새로 할당하지 않는다.
- **같은 애니메이션으로 다시 `SetAnimation`**: 처음부터 다시 시작한다(기존 `Play`와 같음, 설계 판단). 매 프레임 부르는 코드는 `GetTrackAnimation`으로 확인하고 부르도록 README 예제에 적는다.

**시간 진행**: 항목마다 `time += dt × timeScale`. 반복이 아닌 항목은 끝에 닿으면 끝 프레임을 유지한다(지금 컴포넌트와 같음). 섞는 중인 이전 항목도 시간이 흐른다. 섞기가 끝나면 이전 항목을 버린다.

**공개 API**(컴포넌트 `KGBoneAnimation`에 둔다, 이름은 확정):
- `SetAnimation(int track, string name, bool loop, float mix = -1)` — 그 트랙의 지금 항목을 바꾼다. `mix < 0`이면 `defaultMix`를 쓴다. 예약은 비운다.
- `AddAnimation(int track, string name, bool loop, float delay = 0, float mix = -1)` — 지금 항목이 끝나면(반복이면 이번 바퀴가 끝나면) `delay`초 뒤 시작한다. 트랙이 비어 있으면 `delay` 뒤 바로 시작.
- `ClearTrack(int track, float mix = -1)` — 그 트랙을 `mix`초 동안 서서히 빼고 비운다. `AddEmpty(int track, float delay = 0, float mix = -1)` — 같은 일을 예약으로.
- `SetTrackAlpha(int track, float alpha)` — 트랙 비율(0~1).
- `GetTrackAnimation(int track)` — 지금 항목 이름(없으면 null).
- 이벤트 `TrackCompleted(int track, string name)` — 반복 아닌 항목이 끝에 닿은 프레임에 한 번. 기존 `Completed`는 트랙 0에 대해 그대로 낸다.
- 필드 `defaultMix`(초, **기본 0**: 아무것도 안 바꾸면 지금처럼 바로 바뀜 — 목표 6).

**에디터 모드(플레이 전 씬 화면)**: 지금처럼 인스펙터의 `skin`·`animationName` 0초만 그린다. 트랙·`SetSkins`·첨부물·본 덮어쓰기는 코드에서 부르는 실행 중 상태라 저장(직렬화)하지 않고, 플레이 모드가 끝나면 사라진다. 인스펙터에 새로 생기는 필드는 `defaultMix` 하나다(설계 판단).

**기존 API와의 관계**:
- 인스펙터의 `animationName`·`loop`·`playOnAwake`는 트랙 0의 시작 애니메이션이다. 실행 중 `animationName`을 바꾸면 `SetAnimation(0, …, defaultMix)`와 같다.
- `Play(name, loop)` = `SetAnimation(0, name, loop)`. `Stop()` = 모든 트랙 즉시 비우기 + 셋업 포즈(지금과 같음).
- `Time`, `CurrentAnimation`, `IsPlaying`은 트랙 0의 지금 항목 기준.

**이벤트**: 각 트랙의 지금 항목에서 [이전 시간, 지금 시간) 구간 이벤트를 낸다(트랙 순서대로). `KGBoneEvent`에 `Track`(트랙 번호)과 `Animation`(애니메이션 이름) 필드를 더해, 공격 트랙의 타격 이벤트와 걷기 트랙의 발소리를 구별하게 한다(기존 생성자는 남겨 Track 0·이름 null로 채움 — 기존 코드 그대로 컴파일됨). 섞이며 빠지는 이전 항목의 이벤트는 내지 않는다(설계 판단: 공격을 끊고 바꿀 때 끊긴 공격의 타격 이벤트가 나지 않게). 물리 reset 키도 지금 항목만 본다.

### 5.4 묶음 ③: 첨부물·스킨 합치기·본 덮어쓰기
- **첨부물 덮어쓰기**: `SetAttachment(string slot, string attachment)` — 애니메이션의 첨부물 키보다 우선한다(덮어쓰기가 켜져 있는 동안). `attachment = null`이면 그 슬롯을 숨긴다. `ClearAttachment(string slot)`로 애니메이션·셋업 값으로 돌아간다. 없는 슬롯·첨부물은 경고 로그 한 번 뒤 무시.
- **스킨 합치기**: `SetSkins(params string[] skins)` — 여러 스킨을 함께 켠다. 같은 (슬롯, 이름)의 첨부물은 **뒤에 적은 스킨이 이긴다**. 스킨 전용 본·제약은 켠 스킨 중 하나라도 가지면 켜진다. 기본 스킨은 지금처럼 항상 포함. 기존 `skin` 필드는 스킨 하나만 켜는 것과 같고, `SetSkins`를 부르면 필드를 그 첫 번째 값으로 맞춘다. 스킨을 바꾸면 물리를 초기화한다(2단계와 같음).
  - 계산부는 스킨 하나(문자열) 대신 "켠 스킨 목록"을 받는다. 스킨이 하나면 지금과 같은 경로라 정답이 그대로다.
- **본 덮어쓰기**: 본마다 하나, 해제할 때까지 매 프레임 유지된다.
  - `SetBoneLocal(string bone, BoneOverride value)` — `BoneOverride`는 `Rotation`, `X`, `Y`, `ScaleX`, `ScaleY` 중 정한 것만(nullable) 바꾸고, `Mix`(0~1, 기본 1) 비율로 애니메이션 값과 섞는다(각도는 짧은 쪽). 값은 **절대 로컬 값**(에디터 속성 패널에 보이는 본의 회전·위치·크기, 부모 기준)이다(설계 판단: "고개 회전 = 30°"처럼 그대로 넣으면 되도록). 셋업 대비 값이나 더하는 값은 두지 않는다.
  - 월드 → 로컬 변환은 본의 상속 설정(회전·크기 상속 끄기 등)을 따른다. 핵심 `BoneTransform`의 로컬→월드 계산을 거꾸로 푸는 것으로 하고, 2단계에서 만든 `BoneTransform.WorldToLocal`/`SetWorld`를 쓴다.
  - `SetBoneWorldPosition(string bone, Vector3 position, float mix = 1)` — 유니티 월드 좌표의 점을 본 원점의 목표로 준다(마우스 따라 IK 대상 옮기기). 부모 월드 기준 로컬로 바꿔 넣는다.
  - `SetBoneWorldRotation(string bone, float degrees, float mix = 1)` — 본 X축의 유니티 월드 방향(도)(마우스 따라 고개 돌리기).
  - `ClearBone(string bone)`, `ClearAllBones()`.
  - 월드 값은 GameObject의 위치·회전·크기, `flipX`/`flipY`, `pixelsPerUnit`을 반영해 뼈대 좌표로 바꾼다(`TryGetBone`의 반대 변환).
  - 덮어쓰기는 제약 앞에 들어간다. 그래서 IK·트랜스폼 제약이 덮어쓴 본을 다시 바꿀 수 있다(IK 대상 옮기기가 이 덕에 된다). 제약이 걸린 본 자체를 덮어쓰면 제약 결과가 이긴다(설계 판단, 문서에 적는다).

## 6. 정한 것 요약
- 사용자 결정: 방법 A(번호 트랙). 쓰는 장면은 걷기·달리기 중 공격, 무기 갈아 끼우기, 마우스 따라 고개 돌리기.
- 설계 판단(틀리면 고칠 것):
  - 세 묶음(① 시퀀스·클리핑 ② 트랙 ③ 첨부물·스킨·본 덮어쓰기), 묶음마다 push.
  - 섞기는 두 포즈를 만들어 섞는다(셋업으로 꺼지지 않게). 윗 트랙은 키가 있는 값만 바꾼다. 본 마스크·트랙 더하기는 넣지 않는다.
  - `defaultMix` 기본 0(기존 동작 유지). 섞이며 빠지는 항목의 이벤트는 내지 않는다. 이벤트에 트랙 번호·애니메이션 이름을 담는다.
  - 섞는 도중 또 바꾸면 그 순간 포즈를 얼려 두고 거기서 섞는다. 같은 애니메이션으로 다시 부르면 처음부터.
  - `SetBoneLocal` 값은 절대 로컬 값. 새 기능은 플레이 모드 실행 중 상태(저장 안 함), 인스펙터 새 필드는 `defaultMix`뿐.
  - 덮어쓰기는 애니메이션 뒤·제약 앞. 제약이 걸린 본 자체는 제약이 이긴다.
  - 스킨 합치기는 뒤 스킨 우선. 첨부물 덮어쓰기는 애니메이션 키보다 우선.
  - Animator·Timeline, 루트 모션, 에디터 정지 시 물리 미리보기는 이번에 하지 않는다.
