## Spine 4.3 JSON 호환 미확인

- **G-11** 슬라이더 제약의 JSON 표기 미확인 → Spine JSON 내보내기에서 제외하고 경고. .kgbone에는 모두 저장된다.
- **G-12** IK·물리의 부피 보존(scaleY) JSON 키 미확인 → 내보내기에서 제외하고 경고.
- **G-13** 4.3 JSON의 "가독성·크기·정밀도 개선"(S4)이 구체적으로 무엇인지 미확인 → 4.2 문서 구조로 읽고, 모르는 키는 보존만 한다.
- **G-14** atlas 회전 영역의 `bounds` 폭·높이를 "페이지에 놓인 그대로"로 해석(90·270도면 원래 방향으로 바꿔 보관). 공개 아틀라스 문서로 확인 못 함.
- **G-15** Spine 키 값이 생략됐을 때의 기본값 일부 미확인: alpha 1, scale·scalex·scaley 1, 물리 mix 1·그 밖 0, 시퀀스 mode "hold". 읽기·쓰기는 서로 맞춰 둠.
- **G-16** 클리핑 `inverse`·`convex`(4.3)의 JSON 키 이름 미확인 → 켜졌을 때만 이 이름으로 씀.

## 실행 파일
- **G-20** 실행 파일(KGBone.exe)은 코드 서명이 없다. 이 PC는 스마트 앱 컨트롤이 켜져 있어 서명 없는 exe 실행·빌드가 막힌다 → exe는 GitHub Actions에서 빌드하고(`build-output` 브랜치), 이 PC에서는 브라우저 판(`npm run app` / `KGBone 실행.cmd`, Edge 앱 창)으로 실행한다. 서명(인증서) 또는 스마트 앱 컨트롤 해제는 사용자 결정 사항.
- **G-21** Tauri 앱 본체 코드는 이 PC에서 컴파일할 수 없어 CI에서만 검증된다. 파일 연결 등록(reg.exe)·폴더 감시는 실제 실행으로 확인하지 못했다.
- **G-22** 브라우저 판의 파일 연결(더블클릭 열기)은 Edge에서 "앱으로 설치"한 경우에만 된다(매니페스트 file_handlers + launchQueue). 실제 더블클릭 실행은 설치한 PC에서 손으로만 확인할 수 있고, 자동 테스트는 받은 파일을 꺼내는 함수와 매니페스트 선언까지만 본다. File System Access 폴더 고르기 동작은 자동 테스트가 없다(경로 표만 테스트).
  - Windows판 Chrome(157에서 확인)은 매니페스트 `file_handlers`의 아이콘을 받아 가지 않아 `.kgbone` 파일 아이콘이 비어 보인다(레지스트리 `HKCUSoftwareClassesChrome.<번호>DefaultIcon` = `,0`). Edge는 앱 아이콘으로 등록한다. 그 값을 앱 폴더의 `KGBone.ico`로 직접 채워 보니(따옴표 없이 `경로,0`이어야 함, 따옴표로 감싸면 아이콘을 못 꺼낸다) Windows 셸은 KGBone 아이콘을 돌려줬지만, 아이콘 캐시 새로 고침·로그아웃 뒤에도 이 PC의 탐색기 화면에는 보이지 않았다. 파일 아이콘이 필요하면 Edge로 설치한다.
- **G-23** 웹 판(GitHub Pages)의 서비스 워커는 빌드 결과에서 목록이 채워지는지만 자동 테스트한다. 오프라인 실행은 로컬 서버에서 캐시가 채워지는 것까지 손으로 확인했다.
- **G-24** MCP 서버(tools/mcp)의 `render`는 이미지가 붙은 첨부물만 그린다(본·경계 상자·패스는 안 그림). 시점은 fps 간격의 가장 가까운 프레임으로 맞춘다. 화면 전용 명령(scope: ui, 선택·보기 등)은 쓸 수 없다. PNG 알파 읽기는 인터레이스 PNG를 지원하지 않는다(크기만 등록).
- **G-25** 뷰포트에서 첨부물 끌어 옮기기(D14)는 이미지(region)만, 셋업 모드에서만 된다. 메시는 정점 편집으로, 애니메이트 모드에서 그림 위치를 바꾸는 키는 없다(첨부물 위치는 키 대상이 아님). 회전·크기 도구로 그림만 돌리거나 키우는 기능은 없다(속성 패널 숫자로).
- **G-26** 유니티 런타임(`unity/com.kgbone.runtime`)은 재생 + 본 위치 읽기와 제약 5종(물리 포함)을 계산한다(2단계). 물리는 애니메이션이 멈춰도 진행하고(에디터는 멈춤), GameObject 이동·회전 반영(반영 값 > 0)은 에디터에 없는 동작이라 정답 비교 없이 방향·비율 단위 테스트로만 확인했다. 클리핑·시퀀스는 3단계에서 핵심과 같게 그린다. 단 유니티(Mono)는 float 셈 정밀도·삼각함수 끝자리가 핵심과 조금 달라, 오목 다각형 **반전** 클리핑에서 조각 경계에 생기는 넓이≈0 조각이 핵심과 다르게 남거나 빠질 수 있다(보이는 결과는 같음, 정점 목록만 다름). 그래서 정답 파일의 반전 클리핑은 볼록 다각형으로 두고, 오목 반전은 dotnet 단위 테스트(`m18_clip_square_by_concave_polygon`)로 본다. 번호 트랙·섞기는 핵심(에디터)에 없는 기능이라 정답 비교 없이 단위 테스트로 확인했다(트랙 하나·섞기 없음이면 일반 재생과 비트 단위로 같음). 트랙 더하기(additive) 섞기·본 마스크·루트 모션은 없다. 한 프레임 안에 섞는 중인 트랙을 두 번 이상 바꾸면 중간 것은 버리고 첫 번째 순간의 모습에서 섞는다. 스킨 합치기, 코드로 본 덮어쓰기는 3단계에서 진행 중이고, Animator·Timeline 연동은 없다. 계산하지 않는 제약 종류는 가져올 때 경고한다.
- **G-27** 유니티 런타임의 이벤트 시간은 핵심과 같이 키에 적힌 시간이다. 반복 재생에서 길이와 같은 시간의 키는 프레임 경계가 정확히 그 시간에 걸리면 나지 않는다([이전, 지금) 구간 규칙). 반복하지 않는 재생은 끝에 도달한 프레임에 끝 시간 키(길이 0이면 0초 키)를 보태 내보낸다(핵심의 한 번 계산에는 없는 재생 컴포넌트의 규칙). timeScale이 음수면 이벤트를 내지 않는다.
- **G-28** 유니티 런타임은 Unity 6000.3 + URP 17.3에서만 확인했다. 패키지가 요구하는 URP 17.0.3(Unity 6000.0 기준)과 Unity 6000.0~6000.2에서의 동작은 확인하지 못했다. 선형 색 공간(URP 기본)에서는 셰이더가 화면과 같은 감마 공간 계산 뒤 선형으로 바꿔 불투명한 부분은 감마 공간과 같은 색이 되지만, additive·screen 블렌드와 반투명 가장자리는 선형 화면에서 섞여 웹 판과 조금 다르다(확인용 프로젝트 화면 비교: 픽셀 99%가 차이 5 이내). 유니티 EditMode 테스트는 유니티 라이선스가 필요해 CI에서 돌리지 않는다(계산부는 CI의 dotnet test로 확인).

- **G-29** MCP 연결(SPEC N): 한 번에 창 하나만 연결된다([연결]을 누른 창이 가져가고, 자동 연결은 기다림). 설치형 웹 앱(GitHub Pages)에서 연결되는 것은 Edge에서 손으로 확인했다. 보안은 127.0.0.1에서만 열기 + 브라우저 Origin 검사이고, 연결 코드(짝 맞추기)는 두지 않았다 — 이 PC에서 도는 다른 프로그램은 원래 사용자 권한으로 무엇이든 할 수 있어 코드가 지켜 주는 것이 없다고 판단했다. 설치형 웹 앱(https://dudwo2199.github.io)에서 `ws://127.0.0.1`에 붙는 것은 Chrome·Edge의 로컬 네트워크 접근 정책에 따라 허용을 묻거나 막힐 수 있다(자동 테스트는 개발 서버에서만). Tauri 판의 MCP 연결(디스크 경로 바로 읽기)은 이 PC에서 실행할 수 없어 확인하지 못했다. AI가 부른 화면 명령이 대화상자를 열면(예: help.shortcuts, 이미지 이름 없이 이미지 붙이기) 바로 취소하고 실패로 돌려준다 — 대화상자로만 받는 입력은 MCP 연결로 할 수 없다. MCP 클라이언트별 설정(Cursor·Codex·VS Code·Gemini CLI)은 공개 문서 형식대로 사용 설명서에 적었고, 실제로 붙여 본 것은 Claude Code 방식(표준 입출력)뿐이다.
